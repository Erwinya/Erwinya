## How I like to build software

I prefer systems that are easy to reason about six months later. That usually means:

1. **Clear domain boundaries** — each module owns one responsibility
2. **Layered backend design** — HTTP, business logic, and persistence stay separated
3. **Explicit contracts** — DTOs, validation, and documented APIs
4. **Operational practicality** — Docker, local profiles, and configuration that others can run quickly
5. **Incremental quality** — useful tests first, then deeper coverage where risk is highest

I am comfortable moving between Java-centric Spring services and Python/Django APIs depending on the problem. For industrial contexts, I prioritize reliability, readability, and integration-friendly design over clever abstractions.
